# Local consumer qualification before prerequisite publication

The approved prerequisite must be proved through Tenants' actual domain and actor
hosts before a release is treated as a working solution. After upstream focused
checks and parent inspection, create an exact committed local EventStore candidate
and retain its complete source/tree, package, API and source-preservation receipts.

A disposable package feed may contain candidate EventStore packages only for a
clearly labeled prerelease consumer/runtime diagnostic. It is not a published
prerequisite, adoption baseline or successful final released bootstrap. Preserve
production policy and all CI/security checks. Use the exact same package boundary
that the later public release will supply; no ordinary library source-reference
substitution. Test the real processor/discovery/replay/bounded router and actor
configuration rather than a cohost-only registry workaround.

Bind all candidate archives to the committed upstream source and their payload
hashes, constrain exact candidate package IDs to the private feed, and verify
actual restored assets/assemblies against those inputs. Keep feeds, cloned direct
dependencies, NuGet cache and all runtime resources below run-with-temp TMPDIR.
Mount no host socket, home or publishing credential; retain only support-safe
evidence and finish/clean all own jobs. Ordinary published dependencies retain
their actual versions, and no synthetic published tag or delivered CI file is
created.

The subsequent Tenants implementation slice can use this feed for development
and genuine module finite serializer/state parity qualification. Its approved
source graph may then reference the new upstream candidate in an explicitly
local diagnostic. Keep owned Builds content unchanged. Native/500K checks stay
parent-owned and sequential after the child closes all work. Preserve the full
workload, constraints and refusal controls. Reconcile the documented snapshot
interval50 with actual observed100 explicitly, without an undisclosed tuning
change or reduced workload.

Only an authenticated compatible public release can satisfy the prerequisite.
After publication, repeat the final exact-source qualification using those actual
released inputs, then proceed with the remaining registration/adoption/credential
cleanup/hosted/scheduled acceptance. Candidate-feed success cannot replace that
proof. Existing EventStore publication/adoption pipeline defects remain separate
work in the owning CiCd policy.
