# Complete mode: reruns finish from the original artifact

<intent-contract>

## Intent

**Problem:** Resolve can select a marked draft and the publisher can replay its original payload, but the reusable release still skips draft processing in complete mode and fails. An interrupted release needs an authenticated handoff from the run that created its draft, and an expired artifact must never cause a version to be rebuilt from different content.

**Approach:** Extend the existing draft stage to authenticate the saved producer and artifact and return the existing publication handoff. If that artifact is unavailable and any NuGet package is listed, retain the marked draft and fail. Automatic deletion requires an explicitly empty package inventory and definite absence of every listed image/version; otherwise retain the draft and fail. This invocation delivers planning only.

## Boundaries & Constraints

**Always:** Follow CAP-12 and AD-16/17, with AD-7/9/11/19/20. Implement in `references/Hexalith.Builds` using trusted action-path stdlib Python >=3.12 and bare Git data reads. The draft job retains exactly `contents: write` and `actions: read`; only the existing pull-only registry pair may additionally reach it. Preserve the strict switch, dispatch-SHA configuration, source selection, create-mode behavior, current-dispatch CodeQL/nightly gates, and exclusive outcome ownership. Complete mode skips version/build, draft-SHA drift/CI/audit checks and historical configuration loading. Current-dispatch nightly analysis and hook preparation still run as AD-17 requires.

Authenticate the selected bot draft and exactly five trailers, including explicit empty inventories. Use its saved run ID and exact artifact ID/digest, never a name search or the current run's artifact. The original run must match the current caller workflow path from `github.workflow_ref`, `workflow_dispatch`, `main` and the draft SHA. Missing or identity-mismatching original runs count as no artifact; unrelated transport, authorization and malformed-response errors fail without deletion. An API digest disagreement always fails, even when expiry is also reported. Validated expiry or definitive artifact disappearance permits only the conservative stale branch. Preserve original archive/package/OCI validation and publisher reauthentication.

When the original artifact is unavailable, any nonempty authenticated NuGet package inventory requires retaining the draft and failing with `draft vX.Y.Z cannot be completed: its build artifact is gone`. NuGet HEAD 404, other anonymous lookup results and elapsed time cannot authorize deletion; no quiet period applies. This includes unlisted packages, packages still in validation/indexing and mixed package/container inventories. Manual disposition requires a separate human decision that preserves the prohibition on reusing a version with different content. This refusal does not apply when the authenticated original artifact is usable: complete mode still hands off those identical bytes.

Automatic deletion requires an explicitly empty package inventory and a definite not-found for every listed container version. A published image, missing pull credentials, redirect, throttling, authorization error, malformed response or timeout counts as existing for this decision. Explicitly empty package and container inventories need no destination requests. Revalidate the same live marked draft immediately before deletion. Confirm HTTP 204 before emitting `stale-draft-deleted`, `publish=false` and `nothing`; do not start create mode in that run.

For the re-drive, amend the delivered recovery forward from the current Builds `main`, preserving `dd68a5efbfaec13ef22ec06ad151b212eb16ea4f` and subsequent commits. Do not revert the delivered recovery or reapply `_bmad-output/implementation-artifacts/3-5-followup-review-intent-gap.patch`: its changes are already present. The planning-only delivery instructions below describe the completed planning invocation.

**Never:** Rebuild, repack, relabel, replace or republish the version from different bytes; create a replacement draft/version, delete/move a Git tag, delete published packages/images, or touch unmarked drafts. Do not run source code, checkout, SDK, npm, NuGet login or registry push in recovery. Do not give recovery push credentials, OIDC or attestation permission. Preserve frozen legacy files, production callers/`builds-release.yml`, root package/release configuration, spike evidence and retained 3-4 resources. ## Design Notes

Availability and authenticity are separate decisions. An unavailable run/artifact can permit a destination-absence check; it never permits trusting unvalidated inventory or regenerating bytes. A mismatched API digest is a hard failure. Publisher remains a second independent authenticator after the reusable workflow handoff.

The current draft's saved run is authoritative across different dispatches and rerun attempts. The recovery adapter defaults to create for existing callers and selects complete only from validated resolve outputs. Captured `last-tag` is checked for ancestry rather than recomputed from moving main. No new public schema or publisher input is needed.

Primary protocol references: [NuGet package content](https://learn.microsoft.com/en-us/nuget/api/package-base-address-resource) documents service-index discovery, exact-version content, HEAD and unlisted versions; [Distribution existing manifests](https://distribution.github.io/distribution/spec/api/#existing-manifests) specifies manifest HEAD; [GitHub release deletion](https://docs.github.com/en/rest/releases/releases#delete-a-release) specifies Contents write and HTTP 204. Recovery applies the stricter contract that uncertainty retains the draft.

Planning used only the restricted CiCd-agent profile. `gh variable get HEXALITH_RELEASE_PUBLISH_ENABLED` is unsupported by this installed CLI; the supported REST read `gh api repos/Hexalith/Hexalith.Builds/actions/variables/HEXALITH_RELEASE_PUBLISH_ENABLED` returned HTTP 403, `Resource not accessible by personal access token`. The live switch is unverified, not absent; its future hosted preflight is distinct from planning readiness. No administration or token expansion is part of this story.
